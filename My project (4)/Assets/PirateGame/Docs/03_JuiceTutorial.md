# Juice 실습 안내

## 실습 방식
기본 게임을 먼저 한 라운드 플레이하세요. 기본 버전은 의도적으로 효과가 없습니다.
Scripts/Juice 안의 파일에는 클래스와 TODO 주석만 있습니다.
각 장의 코드를 **해당 파일의 전체 내용으로 교체**하고, 컴파일이 끝난 뒤 컴포넌트와 참조를 연결합니다.
아홉 파일을 한꺼번에 완성하지 말고 한 기능씩 켜고 꺼서 차이를 비교하세요.
문서의 코드는 직접 작성할 때 참고할 완성 예제이며 기본 게임에는 미리 적용하지 않았습니다.

## 공통 이벤트 연결 원리
모든 전투 이벤트는 Game Systems의 CombatFeedbackEvents에서 발생합니다.
씬에 하나만 존재합니다. 전투마다 생성되는 선박 프리팹은 OnEnable에서 이벤트 허브를 찾습니다.
OnDisable에서는 반드시 같은 메서드를 구독 해제합니다.
예제는 이름 있는 메서드를 사용하므로 +=와 -=를 같은 쌍으로 작성할 수 있습니다.
람다를 매번 새로 만들어 해제하면 다른 델리게이트가 되어 해제되지 않습니다.

- ShotFired: 발사 성공. 재장전 중/사거리 밖/UI 클릭 시 발생하지 않음.
- Hit: 실제 피해 적용 후. 대상 ShipHealth를 비교하면 자신이 맞았는지 구분 가능.
- Sunk: 내구도 0이 된 한 번. 대상은 즉시 파괴하지 않고 2초 유지.
- WaterMiss: 최대 거리 도달/섬 충돌. 실제 포탄 위치 사용.

프리팹에는 씬의 허브나 카메라 참조를 저장할 수 없습니다.
따라서 씬에 배치하는 효과 컴포넌트는 Inspector로 연결하고, 선박 프리팹은 허브를 실행 중 찾습니다.
이 방식은 한 씬 학습 프로젝트를 위한 선택입니다. 프로젝트가 커지면 생성 시 의존성 주입으로 바꿀 수 있습니다.

## 매 장의 완료 기준
1. Stop 상태에서 코드와 프리팹을 수정합니다.
2. Inspector의 모든 참조를 연결하고 프리팹/씬을 저장합니다.
3. 같은 Round1을 플레이하며 해당 효과를 확인합니다.
4. 컴포넌트 체크를 꺼 효과가 없는 상태와 비교합니다.
5. 두 번 이상 다시 출항하여 이벤트가 중복되거나 효과가 남지 않는지 봅니다.
6. Console 오류가 0개인지 확인합니다.

마지막 적 격침 시 기본 게임은 즉시 결과창으로 이동합니다.
카메라 흔들림과 Hit Stop은 전투 종료 시 복구하는 정책입니다.
격침 Visual과 파티클은 결과창 뒤에서 수명 동안 마무리됩니다.
극적인 슬로모션 뒤 결과창을 띄우는 연출은 이후 확장 과제로 남깁니다.
