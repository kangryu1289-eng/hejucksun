# 검증과 문제 해결

## 개발 검증
Unity 에디터 메뉴 **Pirate Game > Run Gameplay Checks**를 실행합니다.
현재 씬을 저장한 다음 실행하세요. 기본 게임 씬을 열고 Play에 들어가 검사를 마친 뒤 자동으로 정지합니다.
결과는 프로젝트 루트의 Logs/PirateGameValidation.txt에 기록됩니다.
초기 빈 Juice 상태를 전제로 하는 회귀 검사입니다. 효과를 구현한 후에는 해당 실습의 수동 완료 기준도 확인하세요.
검사 도중 입력·클릭으로 개입하지 마세요. 테스트가 배와 적 AI의 일부 입력을 제어합니다.

## 이번 구현에서 수행한 검증
Unity 6000.0.57f1의 별도 임시 프로젝트에서 검증했습니다.
원래 열린 프로젝트의 UI를 조작하지 않고 Unity 배치 모드로 실행했습니다.

- C# 런타임 및 에디터 코드 컴파일.
- 실제 기본 씬과 프리팹 생성, 직렬화된 참조 로드.
- 경제 계산, 수리 반올림, 자금 부족 처리, 강화 한도.
- 화면 버튼을 통한 정비·라운드 선택·출항.
- 물리 선박 이동·선회, 전장 경계 제한.
- 사거리 밖/최소 거리 이내 발사 거절, 재장전 제한·복구.
- 실제 포탄 이동과 명중, 적용된 강화 데미지, 자신의 포탄으로 자기 배를 맞히지 않음.
- 적 격침 이벤트, 전멸 승리, 승리 보상 중복 방지.
- 다음 라운드 내구도 유지와 수리.
- 3개 라운드 적 수, 패배 위로금, 무료50 HP 복구.
- 물 착탄 이벤트와 재출항 후 선박·포탄 정리.
- 적 AI의 자율 접근·발사와 플레이어 피해.
- 총44개 검증 항목.
- 정비·선택·전투·승리·패배 화면을1280×720으로 렌더링하여 레이아웃 확인.
- 문서에만 제공한 Juice 예제9개도 설치된 Unity DLL로 컴파일 확인.

화면 자료는 [Screenshots](Screenshots) 폴더, 세부 판정은 [검증 결과](ValidationReport.txt)를 확인하세요.
마우스/키보드를 실제 장시간 조작하는 수동 플레이와 실습 구현 후 연출의 감각 평가는 별도입니다.
실습 코드의 컴파일 확인은 모든 효과 조합의 플레이 검증을 뜻하지 않습니다.

## 직접 플레이 체크리스트
- [ ] Play 시작 시 Gold100/Hull100/20 damage/0.80s.
- [ ] 강화 전후 공격력과 재장전 시간이 바뀜.
- [ ] W/S 이동과 A/D 선회가 카메라 기준 탑다운으로 보임.
- [ ] 커서 거리 표기와 빨강/초록 사거리 상태가 일치.
- [ ] 사거리 밖/UI 위/재장전 중에는 포탄이 추가되지 않음.
- [ ] 배와 섬의 충돌, 포탄의 섬 차단.
- [ ] 적 전멸 시 승리, 플레이어 격침 시 패배.
- [ ] 승리 내구도 유지, 수리 비용과 차감 일치.
- [ ] 패배 후50 HP와 위로금으로 다시 출항 가능.
- [ ] 라운드1~3 반복, 결과창 왕복을3회 이상 확인.
- [ ] Play 종료·재시작 시 진행도 초기화.
- [ ] Juice 실습 적용 전후를 같은 라운드에서 비교.

## 문제 해결
| 증상 | 확인할 것 |
|---|---|
| Pirate Game 메뉴가 없음 | Console 컴파일 오류 해결, Assets 새로고침 완료 대기 |
| 씬이 없음 | Pirate Game > Create Missing Game Assets. 이름 없는 수정 중인 씬은 먼저 저장 |
| 기존 SampleScene만 보임 | PirateBattle.unity를 단독으로 열기 |
| 화면이 보라색 | Materials/SpriteUnlit의 Shader=Sprites/Default, 복사된 Art 참조 확인 |
| 버튼이 클릭되지 않음 | EventSystem 하나, InputSystemUIInputModule과 기본 UI Actions 연결 |
| 선박이 움직이지 않음 | Game 뷰 포커스, ShipMotor Enabled, Rigidbody2D Simulated, Hull>0 |
| 발사가 안 됨 | 0.7~8m 범위, UI 위가 아닌지, Projectile Prefab/Root/Feedback 연결 |
| 프리팹의 Camera/Feedback가 None | 정상. 출항 시 BattleController가 주입하는 필드 |
| 적이 섬에 걸림 | 기본 AI는 경로 탐색 없음. 다른 각도로 접근해 격침 |
| 효과가 중복됨 | 같은 컴포넌트 중복 부착, OnDisable 구독 해제 확인 |
| Hit Stop 후 멈춤 | unscaledDeltaTime 사용, OnDisable 복구, Flow 참조 확인 |
| 흰색 Flash가 티 나지 않음 | 기본 셰이더의 곱셈 색상 특성. 붉은 틴트 사용 또는 별도 셰이더 확장 |
| 파티클이 남음 | Looping Off, Emission Rate0, Stop Action Destroy |
| 소리가 안 남 | Clip/Source 연결, AudioListener 하나, Mute Audio Off |
| Play를 껐더니 값이 돌아옴 | 실행 중 수정은 저장되지 않음. Stop 상태에서 프리팹/에셋 수정 |

## 범위
라운드 잠금, 영구 저장, 고급 항법·장애물 우회, 모바일 입력, 세로 화면 대응은 포함하지 않습니다.
기본 버전에서는 실제 탄도는 직선이며 포물선 인디케이터는 후속 시각 실습입니다.
소리는 합성 샘플이며 기본 게임에서는 재생하지 않습니다.

## TMP 전환 검증
PirateBattle의 기존 Text 16개를 TextMeshProUGUI로 변경하고, 이미 적용된 TMP 2개를 유지했습니다.
총 18개 TMP 텍스트, Legacy Text 0개이며 UI 코드의 텍스트 필드는 TMP_Text로 연결됩니다.
씬의 객체 ID·레이아웃·패널 참조를 유지했고 동적 텍스트 필드 11개가 모두 TMP 컴포넌트를 참조하는지 확인했습니다.
Unity 배치 컴파일과 기존 게임 루프 검증 44개가 통과했으며, Screenshots의 5개 화면을 TMP 버전으로 갱신했습니다.
